# Query Cloudflare products

Use **Start with** in Explore or the dashboard query editor to load an example, then choose your account or zone and time range. Examples use the same builders as other queries. They do not create resources, enable products, or change ingestion.

The **GraphQL builder** discovers fields, dimensions, filters, time buckets, availability, retention, and query limits from Cloudflare. Presets preserve Cloudflare's aggregation, sampling, and quantile semantics. A disabled dataset or unavailable field requires the corresponding product, plan, or permission; a preset cannot enable it. Raw GraphQL remains available for advanced expressions.

## Retained product logs

For Workers, Containers, R2, AI Gateway, HTTP/firewall, Gateway, audit, and other logs exposed by the SQL catalog, choose **Builder**, search the dataset list, and use **Logs** as the result format. The builder discovers the timestamp and stored columns. Dataset names and availability come from your account; enabling a product does not automatically enable its logs.

SQL results use Grafana's native Logs view and preserve the original structured fields. Display messages use provider message/action/request fields, with structured JSON as the fallback. Severity is retained when present. Numeric timestamps support seconds, milliseconds, microseconds, and nanoseconds. The plugin uses the SQL catalog's timestamp and column metadata, including case-sensitive provider fields.

DLP request/scan/match metrics are available through Gateway HTTP analytics. Inspect retained Gateway HTTP logs for request-level DLP events and use **DLP · profiles** to identify the configured profiles. Posture-check definitions and CASB findings are available through REST; historical posture, CASB, and DEX events require SQL event datasets exposed by Cloudflare.

Cloudflare controls product entitlements, ingestion, sampling, retention, and field availability. The plugin queries product logs through the SQL API only; it never calls the legacy Log Explorer API. A product absent from the SQL catalog cannot be queried through a legacy fallback. These paths do not retrieve data that was never ingested or has expired. Full-range log volume and invocation context use the SQL paths that support them.

## Operational state and history

Choose **Resources and audit**, then an operation. The operation selects account or zone scope automatically. For child resources such as pool health, WAF rules, and deployment history, use **Browse resources** or enter an ID/name or `$variable`. Browsing needs the product's read permission; it is optional when you already know the identifier.

The available operations cover DNS records/firewall clusters, load balancers/pools/origins/health, health checks, edge/custom/origin certificates, tunnels, Workers/Pages/deployments, Containers, Durable Object namespaces, D1, R2, KV, Queues, AI Gateway, AI Search, WAF rules, devices/posture definitions, DEX, CASB, DLP, Gateway rules, and Audit Logs v2.

Use **Table** for inventory and current state. Certificate queries include the provider expiry date, `daysUntilExpiry`, and `expired` when expiry is known. Origin health includes the region, origin, provider health, failure reason, and response time. Tunnel status remains the provider's status; `healthValue` is 1 for healthy and 0 for degraded/down/inactive, with unknown states left unset.

To evaluate current state in a Grafana alert, choose **Time series**, select a numeric field such as `daysUntilExpiry` or `healthValue`, and use a Grafana reduce/threshold expression. Identity fields remain available as series labels. `snapshotTime` records the fetch time. Refreshing a query observes current state; selecting an older dashboard range does not reconstruct past configuration or health.

Deployment histories, DEX metrics, and audit queries use the selected time range. Pages deployment lists are filtered after retrieval because that endpoint has no time filter. Row limits bound results and the Pages deployment scan; increase the limit when searching older Pages deployments. Grafana shows a notice when results may be incomplete. REST queries use the existing timeout, cancellation, retry, and credential handling.

For **Audit Logs v2 · resource change history**, enter the source audit entry ID and its `action_time` parameter. In an audit event's Grafana log details, **Resource history** supplies both automatically. Cloudflare reports history identification as exact, approximate, or unavailable; approximate/unavailable results produce a notice. Audit request/response bodies are omitted from the returned fields.

All operational requests are allowlisted GET operations against Cloudflare's API. Responses exclude credentials, origin headers, deployment environment variables, and raw audit payloads. There is no arbitrary REST URL or write-operation configuration.

## Grafana views

Use Grafana's existing time-series, table, logs, trace, node-graph, variable, annotation, and alert features. The overview and two-panel trace dashboard remain the only included dashboards. Product examples belong in the query editor; a separate dashboard per product is unnecessary.

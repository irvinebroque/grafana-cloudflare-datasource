# Cloudflare platform coverage

Reviewed on 10 November 2026 against the implementation, real Cloudflare schema discovery, account queries, and current public documentation.

## Coverage model

The plugin uses shared Cloudflare query APIs across products. SQL discovery supports the datasets visible to the selected account, including account-specific Analytics Engine and enabled Log Explorer datasets. The GraphQL builder discovers nondeprecated, nonstaging analytics datasets and their fields, dimensions, filters, and ordering from Cloudflare’s schema, then checks the selected account or zone’s settings. Raw SQL and GraphQL remain available for advanced queries.

The live GraphQL catalog exposed **230 account datasets and 60 zone datasets** after filtering. These include variants and overlapping datasets; they are not counts of products or a guarantee that every dataset is enabled. The prior **91/95 SQL query result** also includes empty responses and measures only that account’s SQL catalog, not Cloudflare’s entire platform.

The builder supports scalar fields, nested result fields, scalar/list filters, dashboard time ranges, provider-supported time buckets, dimensions, and bounded row limits. It preserves provider aggregates and quantiles. Nested Boolean filters and fields requiring arguments remain available through raw GraphQL. Schema fields are filtered against `availableFields` when account/zone settings provide it. Disabled datasets produce an actionable error rather than an empty success.

## What the plugin cannot recover

Cloudflare’s [platform tracing](https://developers.cloudflare.com/observability/traces/) does not imply every product currently emits every operation. The datasource accepts the shared trace schema without hardcoded product span names. It displays retained spans and cannot reconstruct omitted spans, external upstream parents, unsampled events, or data beyond retention. Search extrema describe observed samples; span counts can be weighted estimates. A full trace’s waterfall duration describes its returned spans.

For [host-local `cloudflared` metrics](https://developers.cloudflare.com/tunnel/observability/), scrape the connector’s Prometheus endpoint and query the stored metrics with Grafana’s Prometheus datasource. Use a shared OTLP backend, such as Tempo, for traces that must include services outside Cloudflare. Exported R2/S3/Loki logs need the datasource for that storage backend.

Current REST state does not reconstruct historical state. Product inventory, configuration, audit history, and Radar are explicit remaining integrations; schema discovery must not be presented as full coverage of every Cloudflare API.

## Validation criteria

- Fixtures establish parsing, typed parameters, scope, limits, external parents, graph relationships, status, log mapping, and native frame contracts.
- A successful empty API query establishes compatibility for that scope and time range.
- A disabled dataset is recorded separately from an accessible empty dataset.
- Nonempty API responses plus visible Grafana rendering establish a working account roundtrip for that tested query.
- Resource/account data and credentials stay in ignored local files. Only aggregate outcomes belong in this repository.

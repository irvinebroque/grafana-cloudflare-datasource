# Cloudflare platform coverage

Reviewed on 10 November 2026 against the implementation, live schema discovery, account queries, and public API contracts. See [product examples and usage](PLATFORM.md) and the [validation record](VALIDATION.md).

## Coverage model

The plugin uses shared query paths across Cloudflare products:

- **SQL (Builder / Code):** the account's SQL catalog, including enabled observability datasets and Analytics Engine data exposed there.
- **GraphQL (Builder / Code):** discovered account and zone analytics, with fields, dimensions, filters, ordering, time buckets, availability, retention, and provider query limits.
- **Resources and audit:** allowlisted read-only REST operations for current operational state, deployment history, DEX metrics, CASB findings, and Audit Logs v2/history.
- **Analytics Engine SQL / Workers telemetry:** the original APIs for those query languages.

Live discovery exposed **230 account and 60 zone GraphQL datasets**, excluding deprecated and staging nodes. Dataset variants overlap and are not product counts. SQL catalogs depend on the selected account, zone, ingestion, entitlements, and token. The prior **91/95 SQL result** is an account-specific compatibility check, not a platform completeness percentage.

## Validation criteria

- Fixtures establish request scope, typed parameters, injection rejection, pagination, bounds, response projections, timestamp/message mapping, and native Grafana frame contracts.
- A successful empty query establishes API compatibility for that scope and range. It does not establish populated product semantics.
- Disabled products, missing entitlements, and plan/permission failures are recorded separately from empty successes.
- Nonempty responses plus native Grafana rendering establish a working account roundtrip for that tested query.
- Credentials and account-specific captures remain in ignored local files. Only aggregate outcomes belong in this repository.

## Data and API boundaries

Panel queries cover telemetry, operational health, diagnostic events, and retained history. Resource discovery returns IDs and names needed to construct those queries. Standalone configuration and inventory browsing (including DNS record contents, WAF rules, posture definitions, DLP profiles, and Gateway policies) is outside this boundary. Removing these configuration queries does not remove any SQL/GraphQL product analytics or log datasets.

Current REST state does not reconstruct historical configuration or health. DEX, deployment, and audit endpoints provide their own retained history. The plugin does not deploy resources, enable ingestion, broaden permissions, or create simulated traffic to fill empty products.

Platform tracing accepts the shared Cloudflare span schema without Worker-specific span names or empty-parent assumptions. It displays retained spans; it cannot recover omitted spans, external upstream parents, unsampled events, or expired data. Search extrema describe observed samples and span counts can be weighted estimates. The per-trace node graph is not an aggregate service map.

Use Prometheus to collect host-local `cloudflared` metrics. Use a shared OTLP backend, such as Tempo, for traces that include services outside Cloudflare. Exported R2/S3/Loki objects require the datasource for that storage backend. Radar, organization-level administration, and arbitrary configuration APIs are outside the listed gap closure; catalog discovery is not a claim to implement every Cloudflare REST API.
